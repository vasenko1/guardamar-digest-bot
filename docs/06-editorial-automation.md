# Полная автоматизация редакции

## Приоритет

Дайджест должен быть чистой витриной. При сомнении лучше убрать вероятный
повтор, чем оставить перегруженную категорию; все исходные записи и решения
сохраняются для аудита.

## Конвейер

1. Сохранить все самостоятельные текстовые сообщения из Desktop JSON export.
   Повторный экспорт сверяется только внутри реально покрытого им диапазона:
   исчезнувшая публикация помечается как отсутствующая, но сырой текст не
   удаляется.
2. Безопасный предфильтр исключает авторов из `EXCLUDED_SENDER_IDS`, явно
   бессодержательные строки и истёкшие объявления с явной или однозначной
   относительной датой (`сегодня`, `завтра`, день недели). Исходник не
   удаляется; для каждого сообщения пишется решение и код причины в
   `editorial_audit`. Ручные решения предфильтр не перезаписывает.
   Дата `as_of` обязана совпадать с датой подготовки в `Europe/Madrid` даже для
   исторического месяца; устаревший предфильтр блокирует классификацию и
   публикацию.
3. Остальные не-объявления определяются классификатором: погода, новости,
   отзывы, обсуждения и общие вопросы не проходят, а конкретные предложения и
   запросы остаются.
4. Объявление с интервалом, переходящим в следующий месяц, предфильтр сохраняет.
5. Объединить повторы только внутри автора и месяца. Последняя полная
   публикация — каноническая ссылка. Разные объект, город, дата, маршрут,
   услуга, аудитория или направление «ищу/предлагаю» — стоп-признак.
6. Для одинакового намерения и одного потока автора объединять и вероятные
   повторы. Кластер проверять относительно канонической записи, не только по
   цепочке соседних похожестей.
7. Классифицировать только оставшиеся записи. План категорий сохраняется по
   месяцу; строки всегда по-русски, без цен и контактов, с ссылкой в конце.
   Явное намерение «ищу/сниму/куплю/требуется» сохраняется; число спален не
   подменяется числом комнат. Оборванные фразы, скидки, акции и подарки в
   витринной строке запрещены. Если в текущей выборке есть еда или цветы, но
   модель не создала подходящий раздел, он добавляется динамически только для
   этого выпуска.
   Витринная строка обычно занимает 18–45 и не более 60 символов. Раздел
   недвижимости содержит динамические подразделы по намерению: «Сдам в
   аренду», «Сниму в аренду», а при необходимости «Продам» и «Куплю».
   Внутри них строка состоит только из объекта, числа комнат/спален, срока и
   обязательного другого города. Для конкретного автомобиля остаются марка,
   модель, год и обязательный другой город; двигатель, пробег, топливо,
   коробка и комплектация удаляются.
   Классификация не запускается до завершения актуальных предфильтра и
   арбитража, чтобы не расходовать бесплатную квоту на дубли.
8. Перед отправкой превью администратору и публикацией выполнить блокирующую
   проверку: завершённая классификация, ноль спорных дублей, непустые русские
   строки и категории, прямые уникальные ссылки, отсутствие исключённых
   авторов, цен, контактов, общих заглушек и превышения лимита Telegram.

## Надёжность

Все LLM-решения сохраняются сразу и возобновляются после сбоя. При
недоступности моделей детерминированный fallback принимает консервативное
решение; исходные тексты не удаляются.
При новом экспорте неизменённые записи с тем же отпечатком текста и совместимой
категорией переносятся в новый run без повторного LLM-запроса.
При усилении редакционных правил завершённый run проверяется повторно. Только
нарушившие новые правила checkpoints снимаются и отправляются на повторную
классификацию; исправные строки и решения сохраняются.
Безопасные механические сокращения и структурные строки недвижимости сначала
строятся локально, чтобы не расходовать бесплатную LLM-квоту.

Команды контроля:

```text
guardamar-digest prefilter --period YYYY-MM
guardamar-digest prefilter-audit --period YYYY-MM
guardamar-digest dedupe --period YYYY-MM --semantic
guardamar-digest validate --period YYYY-MM
```

`publish` и `preview --send` вызывают ту же проверку автоматически и не могут
отправить невалидный дайджест.

Успешно опубликованные части сохраняются вместе с Telegram `message_id`.
Повторный `publish` пропускает их и продолжает с недостающей части; изменение
текста уже отправленной части блокируется.
