# Требования к проекту

## Техническая среда

- Целевая среда: слабый Android-телефон с Termux.
- Язык: Python 3.12 или совместимая доступная версия Python в Termux.
- Telegram: прямые HTTPS-вызовы Bot API стандартной библиотекой; постоянный
  listener для ручного MVP не требуется.
- Хранилище: SQLite в WAL-режиме; единственный экземпляр бота и единственный писатель.
- В MVP нет постоянного scheduler и resident service: подготовка выпуска запускается вручную после импорта JSON.
- Автозапуск, wake-lock и постоянный scheduler откладываются до перехода на live-сборщик.
- Запрещено требовать Docker, PostgreSQL, Redis, локальную большую LLM, публичный IP или webhook для MVP.

## Доступ Telegram

- Бот добавлен в основную группу администратором с правом публикации; в MVP ему не требуется получать обычные сообщения.
- В конфигурации задаются `source_chat_id`, публичный username группы при наличии и список Telegram user ID администраторов проекта.
- В MVP бот обрабатывает `callback_query` и команды администратора для preview и публикации. `message` и `edited_message` понадобятся только после перехода на live-сборщик.

## Восстановление пропущенной истории

Telegram Bot API не предоставляет боту метод чтения старой истории группы. Поэтому существуют два разных режима заполнения базы:

1. **MVP — импорт периода.** Администратор экспортирует историю группы из Telegram Desktop в JSON. Скрипт `import_history.py` читает экспорт, оставляет сообщения нужного календарного периода и записывает их в SQLite.
2. **Будущий live-режим.** Бот сохраняет новые обновления, пока работает. После краткой недоступности он обрабатывает доступные ожидающие обновления, но не считает это гарантированным архивом.

Импортер обязан быть идемпотентным по `(chat_id, message_id)`, поэтому его можно запускать повторно. После импорта записи проходят те же правила, дедупликацию, пакетную LLM-обработку и ручную проверку. Для публичной группы прямые ссылки восстанавливаются детерминированно из `username` и `message_id`.

В MVP финальный экспорт перед публикацией является источником полноты месяца. После появления live-сборщика система также будет отмечать последовательность ID полученных сообщений. Автоматический вход в личный Telegram-аккаунт, userbot или обход ограничений не используются.

## Хранение исходного сообщения и ссылки

При получении каждого сообщения до обращения к LLM необходимо сохранить:

```text
chat_id
message_id
message_thread_id (если есть)
published_at
edited_at
text
caption
media_type
media_group_id
moderation_status
source_url
```

`source_url` формируется детерминированно из `chat_id`, `message_id` и настройки группы:

- публичная группа: `https://t.me/<username>/<message_id>`;
- приватная супергруппа: поддерживаемый Telegram формат ссылки при известном внутреннем ID, с пометкой о доступности только участникам.

LLM не создаёт, не редактирует и не выбирает ссылку. Перед публикацией ссылка валидируется. При её отсутствии или ошибке запись получает статус `needs_review`.

## Модель данных

Минимальные таблицы SQLite:

```text
messages(
  id, chat_id, message_id, thread_id, media_group_id,
  published_at, edited_at, text, caption, media_type,
  source_url, moderation_status, deleted_at
)

digest_entries(
  id, message_id, period_key, eligibility_status,
  intent, generated_title, approved_title,
  confidence, text_hash, llm_provider, llm_model,
  classified_at, excluded_reason, manual_override_at
)

digest_editions(
  id, source_chat_id, period_key, timezone, status,
  snapshot_at, created_at, published_at
)

digest_edition_entries(
  edition_id, entry_id, edition_category_id, title_snapshot,
  source_url_snapshot, position, included
)

edition_categories(
  id, edition_id, code, title, emoji, sort_order
)

digest_parts(
  id, edition_id, part_no, rendered_html, state,
  telegram_message_id, reply_to_message_id, error, sent_at
)

digest_issues(
  id, entry_id, kind, status, resolution, resolved_by, resolved_at
)

admin_actions(
  id, actor_telegram_id, action, target_type, target_id,
  before_json, after_json, created_at
)
```

Ограничения уникальности: `(chat_id, message_id)` для `messages`, `(source_chat_id, period_key)` для `digest_editions`, `(edition_id, part_no)` для `digest_parts`.

## Допустимые записи

В выпуск включаются только самостоятельные объявления, которые:

- опубликованы в соответствующем календарном месяце;
- существуют в базе на момент фиксации выпуска;
- приняты модерацией;
- не удалены ботом/системой модерации;
- не являются дублем, удалённым текущей системой;
- имеют валидную прямую ссылку;
- не исключены вручную.

Исключаются команды, служебные сообщения, сообщения бота, ответы без самостоятельного объявления, благодарности, обсуждения, явный спам и технические записи.

Альбом с одинаковым `media_group_id` представляет одно объявление. Для объявления используется текст или caption; отсутствие обоих переводит запись в проверку.

## Категории месяца

Набор категорий не является постоянным. Он формируется для конкретного выпуска на основании реально присутствующих объявлений месяца. Ниже приведён ориентир высокоуровневых тем, а не фиксированный справочник:

```text
real_estate       🏠 Недвижимость
transport         🚗 Транспорт и попутный груз
repair            🛠️ Ремонт и мастер
beauty_health     💆‍♀️ Красота и здоровье
education_kids    🎓 Обучение и детское
food_flowers      🍰 Еда и цветы
events            🎟️ Мероприятия и досуг
goods             🛒 Товары
auto              🚘 Авто
work_services     💼 Работа и услуги
documents         📄 Документы
animals           🐾 Животные
other             📦 Другое
```

Для каждого выпуска сохраняется его собственная карта категорий: отображаемое имя, emoji, порядок и идентификатор. Она становится частью snapshot и не меняется после публикации. На следующий месяц карта формируется заново.

Категории должны быть максимально широкими, но не обязаны повторять прошлый месяц. Не создавать отдельные категории для аренды, продажи, поиска, кондиционеров, шахмат, косметологии, детских вещей или отдельных городов: это свойства конкретной строки, а не основания для нового раздела. Если в выборке нет объявлений темы, соответствующий раздел не создаётся. Раздел с одним-двумя объявлениями объединяется с ближайшей понятной широкой темой, если это не искажает смысл. Если объявление подходит нескольким разделам, выбирается один главный по предмету объявления; остальные детали при необходимости остаются в заголовке.

Сначала один сокращённый структурированный запрос формирует план абстрактных
категорий месяца. Затем записи обрабатываются по одной и сразу сохраняются.
Такой режим возобновляется после перезапуска и не теряет весь ответ из-за
обрезанного JSON бесплатной модели.

## Подготовка текста и LLM

Телефон выполняет только лёгкую локальную подготовку:

- выбор `text` или `caption`;
- Unicode-нормализация и очистка повторных пробелов;
- удаление URL, телефонов и технического шума из входа LLM;
- сокращение избыточно длинного текста;
- применение модерации и простых исключающих правил;
- расчёт `text_hash`.

При формировании черновика все новые или изменённые записи текущего периода
обрабатываются одним и тем же компактным структурированным prompt по одной
записи. Ответ возвращает `id`, `include`, `category`, `title` и `confidence`.

Заголовок должен быть нейтральным и рекламно-понятным. Одна строка на iPhone 8
остаётся мягкой целью, а не причиной терять полезный факт: обычно достаточно
40–75 символов, технический максимум — 100. Перенос на всех устройствах
невозможно гарантировать из-за размера шрифта и настроек Telegram. Если формат,
дата, район, срок, число спален, маршрут или другой факт делает строку понятнее
и привлекательнее, он важнее строгой однострочности.

Заголовок не содержит цену, телефон, рекламные эпитеты и лишние emoji. Он обязан сохранять тип намерения («ищу»/«предлагаю») и существенные детали.

Генерация заголовка зависит от выбранной категории:

- не повторять название категории и очевидные однокоренные слова: в разделе «Обучение и детское» писать `Уроки шахмат`, а не `Обучение шахматам`;
- считать Гуардамар городом по умолчанию и не расходовать на него место;
- обязательно назвать другой город, если предмет объявления, услуга, жильё, работа, событие или маршрут находятся вне Гуардамара: `Комнаты в Аликанте`, `Косметолог в Санта-Поле`, `Продажа квартиры в Торревьехе`;
- для маршрутов указывать ключевые точки: `Груз Торревьеха → Понферрада`;
- если исходное объявление предлагает много предметов или услуг, выбирать один–три главных, которые лучше всего отличают его от соседних строк;
- перед фиксацией сравнивать черновой заголовок с другими строками той же категории: не допускать буквального повтора и при возможности менять формулировку или уточняющий признак;
- не выдумывать отличия: если двух одинаковых предложений невозможно честно различить кратким текстом, оставлять минимально необходимый факт из исходного сообщения — бренд, город, срок, направление или число спален.
- предпочитать предмет и фактическое преимущество: `Квартира у моря, 2 сп.` вместо канцелярского `Аренда квартиры`; при этом не добавлять оценочные слова вроде «лучшая» или «выгодная»;
- сохранять тип события и дату, когда они делают строку живой и понятной: `Игра «Мафия», 5 сентября`, а не просто `Мафия, 5 сентября`.

Примеры категориально-зависимых строк:

```text
🎓 Обучение и детское:   Уроки шахмат
🎓 Обучение и детское:   Английский для детей
🏠 Недвижимость:         Комнаты в Аликанте
🏠 Недвижимость:         Квартира, 2 спальни
💆‍♀️ Красота и здоровье: Косметолог в Санта-Поле
🚗 Транспорт и груз:     Груз Торревьеха → Понферрада
```

## Бесплатный каскад LLM

Поддерживаются как минимум два независимо настраиваемых бесплатных провайдера:

```text
primary_free_provider → backup_free_provider → local_rules_fallback
```

Переключение на резерв происходит при таймауте, сетевой ошибке, rate limit, недопустимом JSON или недоступности модели. Результат по одному `text_hash` кэшируется и не перегенерируется без изменения текста или ручной команды.

Если оба провайдера классификации недоступны, уже сохранённый прогресс не
теряется, но стадия остаётся незавершённой и публикация блокируется до
повторного запуска. Для арбитража дублей предусмотрен локальный
детерминированный fallback, поэтому очередь дублей всегда доводится до нуля.

Конкретные бесплатные модели выбираются через конфигурацию, поскольку бесплатные квоты и доступность меняются. В проект не закладывается зависимость от платного API.

## Вёрстка и разбиение

- Формат: Telegram HTML.
- У выпуска есть обязательные хидер и футер.
- Хидер каждой части: `📌 Объявления Гуардамара`, затем `Дайджест за <месяц год> · Часть 1 из N`.
- Хидер каждой последующей части: `📚 Объявления Гуардамар · <месяц год>`, затем `Часть X из N`.
- Футер добавляется только в последнюю часть и содержит: «Актуальность уточняйте у автора.» и кликабельный призыв `Новые объявления каждый день → Объявления Гуардамар`.
- Ссылка подписки в футере ведёт на группу, но не заменяет прямые ссылки на отдельные объявления.
- Строка: `• short_title <a href="source_url">↗</a>`.
- Ссылка всегда является последним элементом строки. Перед кликабельным `↗` используется неразрывный узкий пробел, чтобы он не переносился отдельно от заголовка.
- Все пользовательские значения HTML-экранируются.
- Одна строка и один HTML entity никогда не разрываются.
- Используется безопасный рабочий предел длины сообщения, ниже лимита Telegram.
- Заголовок категории публикуется только вместе хотя бы с одной строкой.
- Малые категории не разрываются, если это возможно.
- Большая категория продолжается с заголовком `Название — продолжение`.
- Количество частей вычисляется до устойчивого результата с учётом строки `Часть X из N`.

## Публикация

- Выпуск создаётся как неизменяемый snapshot предыдущего месяца в часовом поясе `Europe/Madrid`.
- Публикация выполняется последовательно и сохраняет ID каждой части.
- Повторный запуск публикует только части без `telegram_message_id`.
- Ошибки Telegram повторяются с exponential backoff; ошибка фиксируется в `digest_parts.error`.
- Следующая часть может отвечать на первую в основной группе, но каждая часть остаётся читаемой сама по себе.
- Между частями применяется небольшая задержка; публикация не требует блокировать сообщения других участников.

## Интерфейс администратора

Интерфейс доступен только разрешённым Telegram user ID и работает в личном чате с ботом.

Кнопки выпуска:

```text
[Предпросмотр] [Проверить]
[Опубликовать] [Пересобрать] [Настройки]
```

Для записи в проверке:

```text
[Включить] [Исключить] [Категория]
[Изменить заголовок] [Открыть оригинал]
```

Интерфейс не показывает итоговые количественные метрики как обязательную часть отчёта или выпуска.
