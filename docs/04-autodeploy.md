# Автодеплой на Android / Termux

## Цель

Телефон самостоятельно получает проверенную версию бота. Ручное копирование файлов, повторная установка зависимостей и ручной перезапуск после каждого изменения не требуются.

## Разделение версий

```text
main   — разработка и проверка на компьютере
deploy — только версия, разрешённая к установке на телефоне
```

Телефон читает публичный репозиторий по HTTPS и только ветку `deploy`. Незавершённые изменения из `main` на него не попадают. Для чтения не нужны SSH-ключ, GitHub token или авторизация на телефоне.

## Что не попадает в Git

- `.env` с `TELEGRAM_BOT_TOKEN`, `GEMINI_API_KEY` и `OPENROUTER_API_KEY`;
- SQLite-база с сообщениями и созданными выпусками;
- журналы работы;
- Telegram JSON-экспорты;
- виртуальное окружение Python.

Эти файлы существуют только на телефоне и защищены `.gitignore`.

## Устройство на телефоне

```text
~/bots/guardamar-digest/      # production checkout ветки deploy
  .env                         # секреты, не в Git
  state/digest.sqlite3         # состояние, не в Git
  logs/                        # журналы только этого бота
  .venv/                       # отдельное Python-окружение
  src/
  tests/
```

## Обновление

`update.sh` запускается по расписанию и выполняет следующие шаги:

1. Запрашивает `origin/deploy`.
2. Если коммит не изменился — завершает работу.
3. Сохраняет текущий commit как точку отката.
4. Получает новую версию кода.
5. Обновляет Python-зависимости только при изменении `requirements.txt`.
6. Проверяет код через `python -m compileall` и внутреннюю команду диагностики.
7. Перезапускает процесс бота.
8. Проверяет, что новый процесс запустился и отвечает на локальную health-проверку.
9. При ошибке возвращается на предыдущий commit и перезапускает рабочую версию.

Проверка обновлений выполняется с разумным интервалом, например раз в 15 минут. Непосредственно перед месячной публикацией обновление не запускается: выпуск не должен меняться в процессе отправки.

## Процесс бота

Команды импорта, preview и публикации запускаются из `~/bots/guardamar-digest/`.
Настройки читаются из `.env`, а SQLite находится в `state/digest.sqlite3`.

Начиная с октября 2026 live collector запускается короткой командой
`guardamar-digest collect` через существующий `crond` раз в 10 минут и
сразу завершается. Отдельный daemon, runit-сервис и wake-lock для digest-bot
не требуются.

## Выпуск версии

1. Код меняется и проверяется.
2. На телефон допускается только ветка `deploy`.
3. Телефон получает `origin/deploy`, выполняет проверки и применяет версию.
4. При неудаче deployment должен оставить предыдущую рабочую копию и базу без потери данных.

Это не CI/CD со сложной инфраструктурой: GitHub хранит код, а телефон периодически забирает только разрешённую ветку.
